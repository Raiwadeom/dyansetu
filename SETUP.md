# Setting up DyanSetu

Two free accounts, about twenty-five minutes. Until you finish, the app runs on
offline seed data and says so in a banner — so you can keep working meanwhile.

**Firebase** holds accounts and data. **Cloudinary** holds the files.

Everything you paste into `.env.local` comes from those two dashboards. Nothing
in this guide requires a payment method.

---

## Part 1 — Firebase

### 1. Create the project

[console.firebase.google.com](https://console.firebase.google.com) → **Add
project**. Google Analytics is not needed; turn it off.

### 2. Turn on email sign-in

**Build → Authentication → Get started → Email/Password.** Enable the first
toggle only, and save.

### 3. Create the database

**Build → Firestore Database → Create database.** Choose **asia-south1
(Mumbai)** for an Indian college. Start in **production mode** — the next step
replaces the rules anyway.

> The region cannot be changed later without recreating the database.

### 4. Publish the security rules

**Firestore Database → Rules.** Delete what is there, paste all of
`firestore.rules` from this project, press **Publish**.

**This step is not optional.** It is the only thing stopping one student reading
another's records, or any account making itself an administrator.

### 5. Copy the web config

**Project Settings → General → Your apps → Web (`</>`)** → register an app →
copy the `firebaseConfig` values into `.env.local`.

```bash
cp .env.example .env.local
```

## Part 2 — Cloudinary

### 1. Cloud name and API keys

From the Cloudinary dashboard:

- **Cloud name** — shown at the top. Goes in `VITE_CLOUDINARY_CLOUD_NAME`.
- **Settings → API Keys** — the **API Key** and **API Secret**. These go in
  `CLOUDINARY_API_KEY` and `CLOUDINARY_API_SECRET`, both **without** a `VITE_`
  prefix so they stay on the server.

> The API secret is the one genuinely sensitive value in this project. Anything
> with a `VITE_` prefix is compiled into the browser bundle; the secret must
> never be.

### 2. Create a SIGNED upload preset

**Settings → Upload → Upload presets → Add upload preset.**

| Setting | Value |
| --- | --- |
| Signing mode | **Signed** |
| Preset name | `dyansetu_signed` |
| Folder | `dyansetu` |
| Allowed formats | `pdf,jpg,jpeg,png,webp` |
| Max file size | `15000000` |

Signed mode is the important one. It means an upload is refused unless it
carries a signature generated by the server.

### 3. Allow PDF delivery

**Settings → Security → Restricted media types** → untick **PDF and ZIP files**.

New accounts block PDF delivery by default. Miss this and question papers upload
fine, then return 401 when a student clicks download.

## Part 3 — Become the administrator

There is exactly one administrator: **raiwadeomrushikesh@gmail.com**.

1. `npm run dev`
2. **Sign up** with that address and your password.
3. Log out, choose the **Admin** tab, log back in.

The Admin tab appears only on the login form and refuses any other address.
`firestore.rules` backs this up: a document claiming `role: 'admin'` is rejected
unless the signed-in token carries that exact email, so no other account can be
promoted — not even by an administrator.

To move the role, change `adminEmail()` in `firestore.rules` **and**
`ADMIN_EMAIL` in `src/lib/profiles.js`, then re-publish the rules.

## How uploads are secured

The browser cannot upload on its own. Every upload takes two steps:

1. The page asks `/api/sign-upload` for a signature, sending the current
   Firebase ID token.
2. The server **verifies that token cryptographically** against Google's public
   signing certificates — issuer, audience, expiry and RSA signature — then
   reads the caller's own profile through Firestore (so the rules apply) and
   checks the role is faculty or admin. Only then does it sign, using the API
   secret that exists solely in the server environment.
3. The browser uploads directly to Cloudinary with that signature.

What that gets you:

| Attack | Result |
| --- | --- |
| Reading the JS bundle for credentials | Only the public cloud name is there |
| Calling the sign endpoint with no token | 401 |
| Forging a token | 401 — signature check fails |
| Replaying an expired token | 401 — expiry checked |
| `alg: none` header trick | 401 — only RS256 accepted |
| Signing in as a student and uploading | 403 — role checked |
| Asking to write outside the notes folder | 400 — folder allow-list |
| A restricted account uploading | 403 |

`node scripts/test-sign-upload.mjs` exercises each of those.

**Local development works the same way.** `vite.config.js` mounts the same
handler at `/api/sign-upload`, so `npm run dev` behaves exactly like production.

### Deploying

`/api/sign-upload.js` needs a host that runs serverless functions. **Vercel** is
free, needs no card, and hosts the site too — `vercel.json` is already here, so
`npx vercel` works out of the box. Netlify and Cloudflare Pages work equally
well.

Add the same environment variables in the host's dashboard. Keep the split: the
`VITE_` ones are public, the rest are secrets.

> Plain static hosting — GitHub Pages, Firebase Hosting without Functions —
> cannot run the endpoint, so uploads will not work there.

## What lives where

| Data | Where |
| --- | --- |
| Accounts and passwords | Firebase Auth (hashed) |
| Profiles and roles | Firestore `profiles/{uid}` |
| Quiz attempts | Firestore `profiles/{uid}/attempts` |
| Faculty notes | Firestore `notes` |
| Question paper records | Firestore `pyqPapers` |
| Note and paper files | Cloudinary `dyansetu/` |
| The 9,938 quiz questions | Bundled in the code |

The question banks stay bundled deliberately — reading 10,000 documents per quiz
would be slow and burn the daily read quota for nothing.

---

## The one remaining limitation

**Deleting a note removes it from the site, not from Cloudinary.** The Firestore
record is deleted, so students stop seeing it at once. Purging the stored file
needs a second signed server call; for now, clear those from the Cloudinary
Media Library when you want the space back.

## Checking it works

1. `npm run dev` — the demo banner should be gone.
2. Sign up as a student → a document appears under **Firestore → profiles**.
3. Take a practice test → a document appears under that profile's **attempts**.
4. Sign up a second account as **Faculty** → **Upload Notes** → attach a PDF.
   You should see a progress bar, then the note in **Cloudinary → Media Library
   → dyansetu/notes**.
5. Open **Subject-wise Notes** while signed out — the note should download.
6. Delete it from the faculty portal — it should vanish for students.
7. Log in from another browser; quiz progress should follow you.
